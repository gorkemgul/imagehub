# Stable Diffusion 3.5 design

- Date: 2026-10-05
- Roadmap step: 6 in `.ai/GOAL.md` (issue #15)
- Workflow: `.ai/skills/add-or-validate-image-model/SKILL.md`

## Scope

`sd3.5-medium` (`stabilityai/stable-diffusion-3.5-medium`, 2.5B MMDiT-X) and `sd3.5-large`
(`stabilityai/stable-diffusion-3.5-large`, 8.1B MMDiT), text-to-image only, at `full` validation
status, as a new family `stable-diffusion-3`. Both repositories are gated (Stability AI Community
License); the maintainer accepts the license and provides a Hugging Face token.

Out of scope: SD 3.0 medium, large-turbo (follow-up once the family exists), img2img/inpainting,
ControlNet, IP-Adapter, skip-layer guidance (pipeline default off), fp16/bf16 parity.

## Reference

diffusers 0.40.0 `StableDiffusion3Pipeline`, `SD3Transformer2DModel`, `AutoencoderKL`,
`FlowMatchEulerDiscreteScheduler`; transformers 5.18.0 `CLIPTextModelWithProjection` (×2),
`T5EncoderModel`, `CLIPTokenizer` (×2), `T5TokenizerFast`. Every numeric detail follows the
installed source.

## Prompt encoding (as `encode_prompt`)

CLIP-L and CLIP-G: penultimate hidden states (`clip_skip` None) and pooled projections; their
hidden states are concatenated on the channel axis (768 + 1280), zero-padded to the T5 width
(4096), then concatenated with the T5 hidden states on the sequence axis (77 + `max_sequence_length`
256). Pooled: concatenation of both CLIP pooled outputs (2048). Negative prompt encoded the same way
(empty string when none). The reference's exact padding, truncation and dtype handling is followed.

## Denoising and decoding

Flow-match Euler with the published scheduler config; CFG as in the pipeline
(`uncond + g * (cond - uncond)`); timesteps passed to the transformer as the reference does;
decode `latents / scaling_factor + shift_factor`. Defaults from each model card (medium: 40 steps,
guidance 4.5; large: 28 steps, guidance 3.5), 1024×1024, multiples of 16 (patch 2 × VAE 8).

## Memory

fp32: large transformer ≈ 32 GB, T5-XXL encoder ≈ 19 GB, CLIP-G ≈ 2.8 GB, per copy. Component
tests load one pair at a time and free it; end-to-end tests run the reference first, keep its
latents and pixels, free it, then run ours. Large end to end at 1024×1024 on CPU is slow; the
end-to-end step count may be reduced (recorded in the measurements), the seed test uses the defaults
for medium and the reduced count for large if needed.

## Validation

Header checks (sharded and single-file), random-weight parity for the T5 encoder and the SD3
transformer (tiny configs exact; layouts of the full configs on the meta device), T5 tokenizer
parity with fuzz and a per-code-point check, a tiny-snapshot end-to-end comparison with
`StableDiffusion3Pipeline`, then real-checkpoint component parity (three text encoders,
transformer step, VAE, scheduler) and end-to-end parity for both models, plus seed tests.

## Task breakdown

1. T5 tokenizer (Unigram / Metaspace from `tokenizer.json`) + fuzz parity.
2. T5 encoder + random-weight parity.
3. SD3 transformer (MMDiT and MMDiT-X) + random-weight parity.
4. Backend (`stable-diffusion-3` family), prompt encoding, catalog entries, tiny-snapshot tests.
5. Real checkpoints (gated download), parity runs, validation records, docs; PR closes #15.
